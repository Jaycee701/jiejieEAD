================================================================
 jiejieEAD  免安装版 · 使用说明
 国密 & 对称密码渗透工具集（Tauri 桌面 GUI）
================================================================

【怎么打开】
  双击本目录下的  jiejieEAD.exe  即可。
  首次启动会检查内置 Python 环境，约 1~3 秒。

【重要：不要单独拷贝 exe】
  本目录下的 resources 文件夹是程序的"内脏"（内置 Python 3.11.9 +
  密码库 pycryptodome/gmssl/scapy/pyasn1 + mitmproxy 11.0.2 +
  MCP SDK（mcp，供第 7 个页签接入 AI 客户端）+ 业务脚本）。
  若要移动到别的位置/U盘，必须把 jiejieEAD.exe 和 resources
  整个文件夹一起拷走，保持同级关系，否则程序会提示找不到 Python。

【功能模块（对应 GUI 十一个页签）】
  1. [Tab1] 对称加解密    17 种算法 × 6 种工作模式 × 5 种填充，文本与文件加解密：
                   算法：SM4 / AES-128 / AES-192 / AES-256 / DES / 3DES / RC4 / RC5（3 变体）/ RC6（2 变体）/ Blowfish / CAST5 / RC2 / ChaCha20 / Salsa20
                   注：RC5 / RC6 为自实现（pycryptodome 与 cryptography 都没有），
                   已用 RFC 2040 / BouncyCastle 公开向量验证，但纯 Python 实现
                   比原生库慢约两个数量级，大文件会明显变慢；
                   RC2 另有 effective key bits 参数（--rc2-effective-bits，默认 128），
                   ChaCha20/Salsa20 必须提供 nonce（前者 8/12/24 字节，后者只能 8 字节）。
                   模式：CBC / ECB / CFB / OFB / CTR / GCM（认证加密）
                   填充：PKCS#7 / Zero / None / ISO7816 / ANSIX923
                   HEX 密钥与 IV 自动校验长度，Base64 / Hex / Raw 输出。
                   注：GCM 与 PKCS7/ISO7816/ANSIX923 组合能自动发现密钥错误；
                   无完整性校验的组合（如 ECB+Zero）界面会主动提醒人工核对明文。
  2. [Tab2] MITM 自动加解密  基于 mitmproxy 的中间人插件，仅拦截白名单域名，
                   请求解密透传 -> 改包 -> 响应加密回注。
                   支持上面全部算法/模式/填充，与加解密工作台共用同一引擎。
                   启动后在日志面板可复制带 token 的改包地址。
  3. [Tab3] 国密分析      SM3 摘要、SM2 公钥风险审计（9 维检测）、
                   TLCP 国密流量解析（需 pcap 文件）
  4. [Tab4] 文件扫描分析  丢一个文件进去自动分析：识别文件类型（JS/APK/
                   pcap/PEM/二进制…）、检出加密算法（SM4/AES/RSA/MD5…）、
                   识别工作模式与填充（ECB/CBC/GCM、Zero/PKCS7…）、
                   自动提取密钥与 IV，并一键填入工作台或 MITM 页签。
                   【识别到什么就能复现什么】——扫描出的模式/填充会直接带进
                   工作台与 MITM，不会出现"检测到 ECB 但只能跑 CBC"的情况。
                   支持钻包解析 ZIP/APK 内层，离线运行。
                   【v3.1】新增「伪装常量与密钥派生链」：
                   · 自动解码伪装的 base64 常量（如 data:image/png;base64,xxx
                     解出来根本不是图片）、裸 base64、长 HEX 串，并按常见拼法
                     切成候选 密钥/IV/种子（67 字符 → 32+16+16+3）；
                   · 识别「对称加密 → 摘要 → 取字节区间」的派生链，直接给出可执行
                     的 cli_crypto.py --derive 命令；常量与链路同现时自动绑定；
                   · .class/.dex/.jar/.apk/无后缀二进制会先抽可打印串再分析
                     （Java class 常量池里的字符串就是这样拿到的）。
  5. [Tab5] 文件夹整体分析 【新】把整个项目目录丢进去，递归分析其中所有文件，并找出
                   文件之间"串联起来"的密码逻辑（密钥定义在 A、加解密在 B、
                   发请求在 C——单看一个文件永远看不到全貌）。
                   产出：
                   · 跨文件关系图（import 依赖 / 共享密钥 / 符号引用 / 同用密码库，
                     左→右 = 依赖方向，悬停高亮）；共享密钥是最危险的信号；
                   · 数据流链路（取密钥→初始化密码器→加解密→编码→签名→传输），
                     链路缺段即说明保护不完整（例如没有"传输"=可能明文外发）；
                   · 整体总结（在线 LLM，失败自动降级离线规则）；
                   · 解密逻辑【新】把加密逻辑"反过来"写成可执行步骤，并跨文件把
                     「算法」（常在 aes.js）与「密钥/IV」（常在 config.js）拼成完整
                     配方；按密钥真实长度重算位宽（16 字节→AES-128，不是默认 256）；
                   · 粘贴密文直接解密【新】密文整段粘进去就出明文：自动试遍
                     「配方 × 输入形态（Base64/Hex/二次Base64）」，再按明文特征
                     （UTF-8 合法性、可打印比例、JSON 结构、业务字段名）打分选最优；
                     失败时给出每次尝试的原因与排查建议，不会把乱码当成功；
                   · 文件清单表格（相关度/算法/密钥数/角色，一键跳单文件深析）。
                   自动排除 node_modules / .git / dist / build / venv / Pods 等噪声目录；
                   内置文件数与单文件体积上限，防止大目录卡死。
                   【v3.1】新增派生配方与跨文件绑定：把 A 文件里的伪装常量与 B 文件里的
                   派生链线索拼成完整配方（「种子 → AES-CBC(常量A,常量B) → SHA256 → [16:32]」），
                   卡片上可直接「去 Tab 8 派生密钥」，补上种子即可复算出真正的正文密钥。
                   另外归档类文件（.jar/.apk/.zip）不再受 4MB 单文件上限限制（放宽到 64MB）。
                   命令行：folder_crypto_analyzer.py --dir <目录> [--deep] [--no-llm]
                           只看配方：--show-plans；直接解密：--decrypt-text "<密文>"
  6. [Tab6] AI 智能分析  【新】粘贴一段代码/抓包/配置片段，自动判定算法/模式/填充/
                   密钥/IV/编码，并一键回填工作台或 MITM。
                   在线 LLM（OpenAI 兼容接口）为主，离线启发式规则兜底；
                   在线调用失败会自动降级为离线分析（结果标 source=offline-fallback），
                   绝不静默失败。配置保存在 resources\python\ai_config.json。
                   ★ 文件扫描分析页签（模块 4）里也有「④ AI 深度分析」入口，
                     可直接对扫描的文件跑同一套 AI 分析。
  7. [Tab7] MCP 接入 【新】把本工具的密码能力（加解密 / 文件扫描 / 能力矩阵）
                   暴露为 MCP 工具，供 WorkBuddy / Claude Desktop 等 AI 客户端直接调用。
                   GUI 里全程点按钮，不用手抄路径、不用手改 JSON：
                   - 打开页签自动体检：mcp SDK 是否就绪、h11/httpcore 版本、
                     pip check 是否全绿、服务器脚本是否齐全、客户端是否已登记；
                   - 「一键安装 / 修复依赖」：装 mcp，并自动把 h11/httpcore 压回
                     与 mitmproxy 共存的兼容版本（不压回去 MITM 页签会起不来）；
                   - 「stdio 握手自检」：真实拉起服务器跑 initialize -> tools/list
                     -> 真加密 -> 错误密钥必须被拒，全过才算"接入可用"；
                   - 「写入 WorkBuddy / 写入 Claude Desktop」：按本机真实路径
                     合并写入客户端配置，保留其它服务器并自动生成 .bak 备份；
                   - 「生成 / 复制接入配置」：手动粘贴方案，已带 UTF-8 声明
                     （否则工具返回的中文报错在部分 Windows 客户端下会乱码）。
                   mcp 依赖已随包内置（resources\python-embed），开箱即用。
                   * 写入后需重启客户端，或在连接器管理页右上角"自定义连接器"里
                     对新服务器点"信任"，才会真正生效。
                   命令行：mcp_setup.py --status / --install / --config /
                           --write workbuddy|claude / --smoke / --selftest
                   服务器本体：crypto_mcp_server.py（stdio，被客户端拉起，
                   暴露 crypto_encrypt / crypto_decrypt / scan_crypto_file /
                   list_capabilities 四个工具，与 GUI 同源、结果一致）

  8. [Tab8] 摘要 / HMAC / 密钥派生 【新】
                   这三件事在真实目标里几乎总是绑在一起的：密钥是"算出来的"、
                   报文还要签名。以前只能识别出"外层用了 SM4"，解不开也签不了。
                   · 密钥格式：hex / utf8 / base64 / auto
                     —— 代码里 `KEY = "4A7F2C1E9B3D5A08"` 是 16 个 ASCII 字符
                     = 16 字节（UTF-8 字面量），按 HEX 解只有 8 字节直接报错，
                     这是"密钥长度不合法"最常见的根因，界面会主动提示歧义；
                     --keyinfo 可一次看到三种格式各自的字节数。
                   · 摘要：MD5 / SHA-1 / SHA-256 / SHA-512 / SM3，输出 HEX 或 Base64。
                   · HMAC：HMAC-MD5 / SHA1 / SHA256 / SHA512 / HMAC-SM3，
                     HMAC-SM3 与 BouncyCastle 逐字节一致（银行/政务报文签名主力）。
                   · 密钥派生：种子 → 对称加密 → 摘要 → 取字节区间。
                     内置 8 个预设，含白盒前端最常见的
                     「AES-128-CBC(种子) → SHA256 → 取[16:32]」；
                     过程逐步留痕（每步的算法/输入输出长度/结果前缀），
                     一键把派生结果填进工作台或 MITM。
                   · 加解密工作台与 MITM 页签都已支持密钥/IV 格式选择。
                   命令行：cli_crypto.py --keyinfo / --digest / --hmac / --derive
                           （--key-format / --iv-format 控制密钥格式）

  9. [Tab9] 非对称 / 压缩 / 编码链 / 混合信封 【新】
                   真实业务的"组合拳"：公钥包密钥、压缩进编码链、安全键盘信封。
                   · SM2：加解密（C1C3C2 / C1C2C3 两种格式）、签名验签
                     （默认国标 SM3+Z 预处理，支持 DER 签名与"输入已是摘要"模式）；
                     公钥兼容 128 位 HEX（可带 04/0x 前缀）/ Base64 / PEM，
                     私钥兼容 64 位 HEX / Base64 / PEM。
                   · RSA：加解密（PKCS#1 v1.5 / OAEP）与签名验签（v1.5 / PSS），
                     支持 MD5~SHA512；**长文本自动分段**（对应 JS 里的 encryptLong2）。
                     密钥兼容 PEM / DER-Base64 / JSON(n,e[,d]) / HEX。
                   · 压缩：zlib / gzip / deflate / deflate-raw（pako 默认裸流），
                     解压时算法标错会自动依次试其它三种。
                   · 多级编码链：压缩 + Base64/Base64URL/HEX/URL 任意组合、顺序可控，
                     解码自动反序执行，失败时明确告诉你是哪一步。
                   · 混合加密信封：随机对称密钥加密数据 + 公钥（SM2/RSA）加密该密钥，
                     一键生成「包裹密钥 / 密文 / IV」；拿到接收方私钥即可还原。
                   · 生成测试密钥对（SM2 / RSA-2048）便于自测。
                   命令行：cli_crypto.py --sm2 / --rsa / --zip / --chain / --envelope / --keygen

 10. [Tab10] 一键解密 【新】把密文直接贴进去，工具自动走完「分析 → 试解 → 出明文」：
                   ① 形态识别：整段 HTTP / 裸 Base64 / 裸 Base64URL / 裸 HEX /
                      URL 编码(%XX) / 种子前置 /
                      JSON 混合信封(encKey+data+iv 或 ed+sked+iv)；混在源码里的密文
                      会自动被挑出来；形状本身有歧义时(如 32hex+Base64 的多种切法)
                      不硬猜，多种解释都试、由打分与 mac 校验裁决
                   ② 常量获取：从「你贴的文本」「指定的目标目录/JS 文件」
                      「本地知识库」三处挖（复用伪装常量解码与派生链识别）
                   ③ 配方编排：两条路线 —— 对称类「种子派生 → 对称解密 → 压缩还原 → mac 校验」；
                      信封类「私钥解封包裹密钥 → 对称解密 → 压缩还原」（RSA-OAEP/PKCS1v1.5、
                      SM2 C1C3C2/C1C2C3 都会试；解封结果必须是 16/24/32 字节才认）；
                      解不开的编码链先剪掉，避免候选被上限截断
                   ④ 明文打分：UTF-8 合法性 / **按字符**的可打印比例（中文不再被误判成乱码）/
                      JSON 结构 / 业务字段名命中，**能验 mac 就一定验 mac**
                      （mac 算法按字节长度自适应：32B→HMAC-SM3/HMAC-SHA256、20B→SHA1、16B→MD5）
                   ⑤ 输出：明文 + 逐步解密逻辑 + 判定依据 + 全部尝试记录（失败也给原因）
                   绝不把乱码当成功；没有材料时会明确告诉你「需要目标 JS/jar 目录」，
                   而不是瞎猜。常量不预置，只从你提供的材料里来。
                   命令行：cli_crypto.py --auto-solve --text/-file <密文> [--target-dir <目录>]
                   独立用法：cipher_auto_solver.py --text/-file ... [--target-dir ...] [--json]

 11. [样本集] 密文样本集（14 个，全部可一键解出）【新】配套两支脚本：
                   resources\tools\make_cipher_samples.py    生成样本集
                   resources\tools\verify_cipher_samples.py  用一键解密逐个跑并出报告
                   覆盖 7 种分组算法(SM4/AES128/192/256/DES/3DES/RC4)、5 种模式
                   （分组/流算法共 17 种可选，见 Tab1）

                   (Base64/Base64URL/HEX/双层Base64/URL/多级链 + gzip/zlib)、9 种报文形态、
                   以及 RSA-OAEP 与 SM2 两种非对称信封。
                   每个样本目录：cipher.txt 密文 · app.js 目标源码片段 · README.md

                   每个样本都能被工具独立解出，并生成含「解密过程 + 明文 + 依据」的报告。

  横切能力：本地知识库 【新】分析出正确逻辑后自动学习并记录，下次遇到"同样的逻辑"

【MCP 接入（GUI 第 7 个页签，依赖已随包内置）】
  目录 resources\python\crypto_mcp_server.py 是一个独立 stdio MCP 服务器，
  把本工具的加解密 / 文件扫描 / 能力矩阵能力暴露为 MCP 工具，供 WorkBuddy /
  Claude Desktop 等客户端调用。接好后可在客户端直接说"用 jiejieEAD 解密这段
  SM4 密文"，由本服务器真实执行（与 GUI 同源，结果一致）。
  暴露的 4 个工具：crypto_encrypt / crypto_decrypt / scan_crypto_file /
  list_capabilities。

  ★ 推荐：直接打开 GUI 的「MCP 接入」页签，四步全点按钮——
      1) 打开即自动体检（SDK / 依赖兼容 / 脚本 / 客户端登记情况）
      2) 「一键安装 / 修复依赖」（mcp 已内置，一般显示"就绪"，仅重装时用）
      3) 「stdio 握手自检」（真实拉起服务器跑一遍 initialize->tools/list->调用）
      4) 「写入 WorkBuddy / 写入 Claude Desktop」（自动填本机真实路径，合并写入，
         保留其它服务器并生成 .bak-jiejieead 备份；也可「复制配置」手动粘贴）
    写入后需重启客户端，或在连接器管理页右上角"自定义连接器"里对该服务器点
    "信任"，才会真正生效。

  · 命令行等效方式（在 resources\python 目录下执行）：
      python.exe mcp_setup.py --status         体检（加 --json 输出机器可读）
      python.exe mcp_setup.py --install        装 / 修依赖
      python.exe mcp_setup.py --config         生成可粘贴的 mcpServers 配置
      python.exe mcp_setup.py --write workbuddy  直接写入客户端配置
      python.exe mcp_setup.py --smoke          真实 stdio 握手自检
      python.exe mcp_setup.py --selftest       接入向导自身自检

  · 手动配置（不想用写入按钮时）：
      command 指向 resources\python-embed\python.exe，
      args    指向 resources\python\crypto_mcp_server.py，
      建议加 env：{"PYTHONIOENCODING":"utf-8","PYTHONUTF8":"1"}
      （工具返回的 JSON 含中文报错信息，不声明 UTF-8 在部分 Windows 客户端下会乱码）

  · 依赖兼容性（重装依赖时会遇到，GUI 按钮已自动处理）：
      装 mcp 会把 h11 升到 0.16、httpcore 升到 1.0.9，而 mitmproxy 11.0.2 要求
      h11<=0.14.0，不压回去第 2 个页签的 MITM 会起不来（pip 报 dependency conflicts）。
      实测 h11==0.14.0 + httpcore==1.0.7 下 pip check 全绿，两侧共存、握手全通。
      详见使用手册第九节。
